# Битва драфтов · Dota 2 Captains Mode

Веб-игра: два капитана драфтят по правилам Captains Mode (патч 7.41f), после чего движок
оценивает шанс победы и разбирает драфт по линиям, матчапам, стадиям игры, составу и
предлагает альтернативные пики. Можно играть с другом по ссылке, против бота или вдвоём за одним экраном.

В разборе позиции можно переставить руками: движок угадывает, кто на какой роли, а капитан
знает настоящий план — после правки пересчитываются линии, штрафы за роль и итоговая оценка.

## Запуск

```bash
npm install
npm start          # http://localhost:3000
```

Node.js 20+. Данные героев и статистика уже лежат в `data/`.

## Онлайн-версия

**https://kioflex12.github.io/dota-draft-battle/** — деплоится автоматически из `main` через GitHub Actions
(`.github/workflows/pages.yml` собирает `public + shared + data` в статический сайт).

Сервера у этой версии нет: комнату держит браузер её создателя, а друг подключается напрямую
по WebRTC (PeerJS, публичный сигнальный сервер + бесплатный TURN Open Relay). Ссылка на комнату
выглядит как `?room=КОД`. Игра с ботом и режим «на одном экране» работают полностью локально.

### Свой сервер комнат — самый надёжный путь

Связь напрямую между браузерами держится на двух чужих бесплатных службах: сервере, который
сводит игроков (PeerJS), и ретрансляторе для сетей со строгим NAT (TURN). Обе могут не работать, и
проверено, что так и бывает: бесплатный ретранслятор Open Relay отвечает отказом на запрос
ретрансляции, а сервер поиска игроков у части людей недоступен вовсе. Тогда игра не соединится,
сколько ни пробуй, — в меню это показывает кнопка «Проверить связь».

Свой сервер снимает обе зависимости: игроки ходят только через него.

**Развернуть на Render (бесплатно, ~10 минут):**

[![Развернуть на Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/kioflex12/dota-draft-battle)

1. Кнопка выше (или New → Blueprint → этот репозиторий). Render прочитает `render.yaml` сам:
   один веб-сервис, `npm install` и `npm start`, порт берётся из окружения.
2. Дождитесь, пока сервис станет `Live`, и скопируйте его адрес вида
   `https://dota-draft-battle.onrender.com`.
3. **Дальше достаточно раздать эту ссылку** — сервер отдаёт и саму игру, и комнаты. Ни сервер
   поиска игроков, ни ретранслятор больше не участвуют.
4. Если хочется, чтобы и ссылка на GitHub Pages ходила через ваш сервер, впишите адрес в
   `public/config.json` и запушьте:

   ```json
   { "server": "wss://dota-draft-battle.onrender.com" }
   ```

   Схему можно не указывать. Проверить без правки файла:
   `…/dota-draft-battle/?server=wss://ваш-адрес` (запомнится в браузере, сброс — `?server=`).

На бесплатном тарифе сервис засыпает после четверти часа без запросов: первое открытие после
простоя занимает полминуты, дальше всё быстро. Комнаты живут в памяти процесса, поэтому инстанс
нужен один — и после перезапуска открытые комнаты пропадают.

Пока `server` пуст, онлайн-версия по-прежнему связывает браузеры напрямую.

**Про «комната не найдена» при открытой вкладке.** Комнату держит не сама вкладка, а регистрация
её создателя на сигнальном сервере. Браузер усыпляет фоновые вкладки, служебные пакеты перестают
ходить, сервер закрывает соединение — и код освобождается. Клиент это отслеживает: создатель
комнаты восстанавливает регистрацию и видит красную полосу, пока связи нет, а входящий делает
несколько попыток, прежде чем сдаться. Если игра всё же не соединяется, сообщение назовёт причину
(недоступен сигнальный сервер, мешает VPN или сеть, браузер без WebRTC).

## Игра с другом через свой сервер

Тот же клиент умеет работать через WebSocket, если его отдаёт `npm start`:

- **Локальная сеть** — друг открывает `http://<ваш-IP>:3000`.
- **Туннель** — `npx cloudflared tunnel --url http://localhost:3000` (или ngrok).
- **Хостинг** — `render.yaml` и `Dockerfile` готовы для Render/Railway/Fly. Нужен один инстанс: комнаты живут в памяти процесса.

Клиент сам выбирает транспорт: пробует `/ws`, при неудаче переходит на WebRTC.

В лобби настраивается: кто пикает первым (жребий как в Dota — победитель выбирает пик или сторону,
случайно, или фиксированно), таймеры (бан I фазы, время на ход, резерв),
что делать с просроченным баном (пропуск, как в Dota, или случайный герой). Просроченный пик — всегда случайный герой.
Ссылка вида `/room/КОД` сразу заводит в комнату (сервер переадресует её на `?room=КОД`).

## Обновление статистики под новый патч

```bash
npm run build-data
```

Скрипт `tools/build-data.mjs`:

1. Берёт героев, способности, таланты и роли на русском из официального фида Valve (`dota2.com/datafeed`).
2. Через SQL-эксплорер OpenDota скачивает публичные ранговые матчи Divine+ с даты патча
   (константы `PATCH`, `PATCH_TS`) — из них считаются винрейты, синергии, контрпики и
   зависимость от длительности игры.
3. Скачивает про-матчи с начала мажорного патча (`PRO_SINCE`) — из них считаются позиции героев,
   исход линий (золото+опыт к 10-й минуте), пик/бан-рейты.

Промежуточные ответы кэшируются в `.cache/`, повторный запуск докачивает только новое.
Сбор занимает ~15 минут (лимит OpenDota — 60 запросов в минуту).

## Проверка движка

```bash
npm run check
```

Печатает снимок оценки на двадцати фиксированных составах — шанс победы, слагаемые, стадии,
кривую, линии, позиции — плюс полный драфт Captains Mode, сыгранный ботом. Заодно проверяет
полосу калибровки, симметрию контрпиков и работу ручной раскладки позиций. Правка формулы почти
всегда выдаёт правдоподобные числа, в том числе с перепутанным знаком, поэтому снимки до и после
сравниваются `diff`:

```bash
npm run check > before.txt
# ...правка shared/analysis.js...
npm run check > after.txt && diff before.txt after.txt
```

## Как считается результат

Все компоненты складываются в лог-оддсы и переводятся в вероятность:

| Компонент | Источник |
|---|---|
| Сила героев в патче | винрейт Divine+ (сглажен) + 15% про-винрейта |
| Синергия | винрейт пары в одной команде относительно ожидаемого |
| Контрпики | винрейт пары друг против друга относительно ожидаемого |
| Линии | позиции по про-данным → 1+5 vs 3+4, 2 vs 2; сила героя на линии, личные встречи, контрпики, дальность атаки/контроль |
| Позиции | штраф, если герою достаётся несвойственная роль |
| Состав | штрафы за отсутствие контроля/инициации/керри/живучести, однотипный урон |

Кривая «шанс победы по минутам» строится из винрейта каждого героя по длительности матча, а
перевес на линиях входит в неё с затуханием: золото и опыт к 10-й минуте решают начало игры и
почти ничего не значат к сороковой.

Альтернативные пики оцениваются не только по матчапу с тем, что уже на столе, но и по риску
ответного пика: чем героя закроют из того, что ещё не забанено и не взято. Поэтому забаненный
контрпик делает предложение безопаснее.

Бот использует тот же движок, и уровни сложности отличаются не случайностью, а взглядом: слабый
видит только силу героя в патче, сильный — связки, контрпики и ответ соперника.

## Структура

```
server/index.js      HTTP + WebSocket-обёртка над RoomManager
shared/room.js       RoomManager: комнаты, лобби, жребий, таймеры, боты (работает в Node и в браузере хоста)
shared/draft.js      порядок Captains Mode, состояние драфта (общий для сервера и клиента)
shared/analysis.js   движок оценки, подсказки, бот, альтернативы
public/              клиент (без сборки, ES-модули); js/net.js — транспорт WebSocket / WebRTC
public/config.json   адрес своего сервера комнат (пусто — связь напрямую между браузерами)
tools/build-data.mjs сбор данных
tools/analysis-baseline.mjs снимок движка для сравнения до/после правки (npm run check)
data/                heroes.json, stats.json
```
