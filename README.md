# Битва драфтов · Dota 2 Captains Mode

Веб-игра: два капитана драфтят по правилам Captains Mode (патч 7.41f), после чего движок
оценивает шанс победы и разбирает драфт по линиям, матчапам, стадиям игры, составу и
предлагает альтернативные пики. Можно играть с другом по ссылке, против бота или вдвоём за одним экраном.

## Запуск

```bash
npm install
npm start          # http://localhost:3000
```

Node.js 20+. Данные героев и статистика уже лежат в `data/`.

## Онлайн-версия

**https://kioflex12.github.io/dota-draft-battle/** — деплоится автоматически из `main` через GitHub Actions
(`.github/workflows/pages.yml` собирает `public + shared + data` в статический сайт).

Сервера у этой версии нет: комнату держит браузер её создателя, а друг подключается напрямую
по WebRTC (PeerJS, публичный сигнальный сервер + бесплатный TURN Open Relay). Ссылка на комнату
выглядит как `?room=КОД`. Комната живёт, пока открыта вкладка создателя. Игра с ботом и режим
«на одном экране» работают полностью локально.

## Игра с другом через свой сервер

Тот же клиент умеет работать через WebSocket, если его отдаёт `npm start`:

- **Локальная сеть** — друг открывает `http://<ваш-IP>:3000`.
- **Туннель** — `npx cloudflared tunnel --url http://localhost:3000` (или ngrok).
- **Хостинг** — `render.yaml` и `Dockerfile` готовы для Render/Railway/Fly. Нужен один инстанс: комнаты живут в памяти процесса.

Клиент сам выбирает транспорт: пробует `/ws`, при неудаче переходит на WebRTC.

В лобби настраивается: кто пикает первым (жребий как в Dota — победитель выбирает пик или сторону,
случайно, или фиксированно), таймеры (бан I фазы, время на ход, резерв),
что делать с просроченным баном (пропуск, как в Dota, или случайный герой). Просроченный пик — всегда случайный герой.
Ссылка вида `/room/КОД` сразу заводит в комнату.

## Обновление статистики под новый патч

```bash
npm run build-data
```

Скрипт `tools/build-data.mjs`:

1. Берёт героев, способности, таланты и роли на русском из официального фида Valve (`dota2.com/datafeed`).
2. Через SQL-эксплорер OpenDota скачивает публичные ранговые матчи Divine+ с даты патча
   (константы `PATCH`, `PATCH_TS`) — из них считаются винрейты, синергии, контрпики и
   зависимость от длительности игры.
3. Скачивает про-матчи с начала мажорного патча (`PRO_SINCE`) — из них считаются позиции героев,
   исход линий (золото+опыт к 10-й минуте), пик/бан-рейты.

Промежуточные ответы кэшируются в `.cache/`, повторный запуск докачивает только новое.
Сбор занимает ~15 минут (лимит OpenDota — 60 запросов в минуту).

## Как считается результат

Все компоненты складываются в лог-оддсы и переводятся в вероятность:

| Компонент | Источник |
|---|---|
| Сила героев в патче | винрейт Divine+ (сглажен) + 15% про-винрейта |
| Синергия | винрейт пары в одной команде относительно ожидаемого |
| Контрпики | винрейт пары друг против друга относительно ожидаемого |
| Линии | позиции по про-данным → 1+5 vs 3+4, 2 vs 2; сила героя на линии, личные встречи, контрпики, дальность атаки/контроль |
| Позиции | штраф, если герою достаётся несвойственная роль |
| Состав | штрафы за отсутствие контроля/инициации/керри/живучести, однотипный урон |

Кривая «шанс победы по минутам» строится из винрейта каждого героя по длительности матча.
Бот использует тот же движок (жадный выбор с шумом, три уровня сложности).

## Структура

```
server/index.js      HTTP + WebSocket-обёртка над RoomManager
shared/room.js       RoomManager: комнаты, лобби, жребий, таймеры, боты (работает в Node и в браузере хоста)
shared/draft.js      порядок Captains Mode, состояние драфта (общий для сервера и клиента)
shared/analysis.js   движок оценки, подсказки, бот, альтернативы
public/              клиент (без сборки, ES-модули); js/net.js — транспорт WebSocket / WebRTC
tools/build-data.mjs сбор данных
data/                heroes.json, stats.json
```
